# ИКИОМА ОС — рабочий контур

Рабочий вертикальный срез операционной системы для строительства частного дома.

В отличие от демонстрационной версии, состояние проекта хранится в серверной
базе, синхронизируется между устройствами и защищено проверкой номера ревизии.
Локальное хранилище браузера используется только как аварийный кэш при
пропадании связи. Один исходный код поддерживает резервный стенд OpenAI Sites
и независимый боевой контур на Timeweb с PostgreSQL и файловым томом.

## Быстрый запуск

```bash
npm install
npm run dev
```

Приложение откроется на `http://localhost:4174`.

Проверка production-сборки:

```bash
npm run build
npm run preview
```

## Timeweb / Docker

```bash
cp .env.example .env
# Заменить все значения replace-with-* и проверить APP_DOMAIN.
docker compose up -d --build
curl http://127.0.0.1/api/health
```

Первый запуск создаёт чистое рабочее пространство. Секреты хранятся только в
`.env`, который исключён из Git. Для временного запуска по IP используется
`APP_DOMAIN=:80`; после подключения домена — `APP_DOMAIN=app.stroios.online` и
соответствующий HTTPS-адрес в `APP_PUBLIC_URL`.

Резервная копия базы и файлов:

```bash
set -a && . ./.env && set +a
./scripts/backup.sh
```

## Что работает

- единая карточка дома и управленческий дашборд;
- финансовая цепочка «план → обязательства → принято → оплачено → прогноз»;
- кликабельные финансовые показатели, статьи сметы и карточки операций;
- производственный график, снабжение и контроль качества;
- карточка закупки с потребностью, этапом, бюджетом, предложениями поставщиков и связанными платежами;
- единая карточка подрядчика или поставщика: связанные этапы, закупки, предложения, обязательства, оплаты, сроки и замечания качества;
- переход в карточку контрагента из финансовой операции, производственного этапа и закупки;
- отдельный справочник контрагентов с контактами, реквизитами, условиями работы и реестром договоров, актов, счетов, ТН и УПД;
- фактическая частичная приёмка и оплата с отдельными суммами, датами и документами;
- реестр нескольких проектов, создание дома по стартовому шаблону и переключение между объектами;
- встроенный центр помощи с пошаговыми подсказками поверх интерфейса;
- серверные проверки Email и Telegram и автоматическая отправка важных событий после подключения защищённых ключей;
- входящий серверный контур заявок с сайта;
- CRM-воронка от заявки до договора с источником, следующим действием и потенциальной выручкой;
- настройки команды, ролевой матрицы, главного дашборда, уведомлений и будущих интеграций;
- фотофиксация, решения клиента и журнал событий проекта;
- серверное сохранение всего состояния проекта;
- локальный аварийный кэш и повторная синхронизация после потери связи;
- защита от незаметного затирания изменений с другого устройства;
- серверный журнал каждой сохранённой ревизии.

## Серверные маршруты

- `GET /api/health` — состояние базы;
- `GET /api/state?projectId=…` — актуальный снимок проекта;
- `PUT /api/state` — сохранение с проверкой ожидаемой ревизии;
- `GET /api/audit?projectId=…` — журнал серверных записей.

## Продуктовые правила

1. Нет оплаты без связи с принятым материалом или работой.
2. Нет закрытия скрытой работы без стандартного комплекта доказательств.
3. Клиентский отчёт формируется из принятых данных проекта.
4. Серверная версия не перезаписывается при конфликте без явного решения пользователя.

Следующий технический слой: персональные учётные записи и серверная проверка
прав на каждое действие, объектное хранилище оригиналов фото, версии сметы и
документов, складские движения и реальные каналы уведомлений.
