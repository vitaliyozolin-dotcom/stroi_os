# Маркетинг и воронка

Четыре сценария — создание заявки, уточнение участка/финансирования, изменение
этапа и импорт сайта — проходят через `application/marketing.ts`. Правила и
подготовка записей находятся в `domain/marketing.ts`, без React, HTTP и БД.
Команды управления формируют StateChange с аудитом и используют общую
синхронизацию с expectedRevision. Сервер сохраняет окончательную проверку прав.

Редактирование существующей заявки проверяет снимок записи и проекта.
Повтор без изменений и продвижение после won/lost не создают аудит. Явный выбор
этапа по-прежнему позволяет открыть закрытую заявку. При ошибке форма сохраняется.

Импорт сохраняет прежний серверный источник `/api/leads?projectId=ikioma-sales`.
Запрос отменяется при смене проекта/размонтировании; результат применяется через
последний снимок, с дополнительной проверкой projectId. Записи дедуплицируются
по ID внутри ответа и относительно состояния. Неверный ответ не применяется
частично, ошибка показывает повтор загрузки. Повторный импорт не меняет уже
имеющиеся заявки, их заметки и этапы. В ошибках нет содержимого заявок.

Формат AppState, схема БД, публичные формы сайта и правила доступа не меняются.
Общий снимок состояния остаётся связью с другими модулями; полноценное разделение
контекстов хранения ещё не выполнено. Проверки: marketing-use-cases.test.ts.
