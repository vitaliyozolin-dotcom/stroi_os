# Решения клиента

`domain/client-decisions.ts` содержит существующие варианты выбора и чистое
подтверждение решения. Варианты пока определяются прежним правилом ID; перенос
самих вариантов в данные требует отдельного изменения контракта.
`application/client-decisions.ts` проверяет роль клиента/управления, формирует
StateChange и аудит с личностью сессии, переданными временем и ID.

Снимок включает проект и целевое решение. Изменённый вопрос, удалённая запись
или другой проект требуют переоткрыть форму. Ошибка сохраняет выбранный вариант.
Повтор подтверждённого варианта не создаёт запись и аудит; другой вариант не
перезаписывает уже принятое решение через этот сценарий. Несвязанные изменения
сохраняются, финансовые факты, этапы и приёмка не меняются.

Команды используют общую синхронизацию с expectedRevision. Серверные проекции
и полномочия сохранены. Новые предметные проверки выполняются в сценарии UI;
отдельного серверного валидатора решений на этом шаге не добавлено. Общая форма
AppState остаётся связью с остальными модулями, схема БД не меняется.
Проверки: client-decision-use-cases.test.ts и действующие access-control.test.ts.

Браузерная проверка с клиентской проекцией и mergeStateForRole подтверждает
сохранение скрытых документов и отсутствие дублей решения/аудита после перезагрузки.
Общий механизм синхронизации может повторно отправить прежнее событие журнала;
серверное объединение дедуплицирует его по ID. Этот механизм здесь не менялся.
