# Общие сценарии web и Telegram, разделение UI — 21.10.2026

## Общие команды

`src/application/tasks-runtime.js` — одна реализация создания, редактирования,
комментариев и смены статуса задач. Web использует типизированный вход `tasks.ts`,
Telegram — адаптер `sites/telegram/business-commands.js` внутри каждого повтора CAS.
`src/domain/task-mutations.js` формирует записи и историю; `mutations.ts`
переэкспортирует эти же функции и сохраняет отдельный переход качества.

`src/application/project-records.js` регистрирует документы и записи дневника.
Web-сценарии загрузки вызывают эти команды после проверки файлов, отмены и
актуальных ссылок. Telegram вызывает их после получения/восстановления вложения
и повторной проверки действующего пользователя внутри CAS.
`src/domain/document-records.js` содержит общие правила метаданных, ссылок и
принадлежности файла проекту; `project-documents.ts` сохраняет типизированный вход.
`module-repository-runtime.js` исполняет тот же контракт scoped-репозитория.

JS-модули нужны для общего выполнения в браузере, Node и Worker без загрузки TS
на сервере. Рядом находятся декларации типов; TS-входы не содержат вторых реализаций.
Новые файлы включены в обе серверные упаковки, архитектурный тест проверяет их состав.

Различия входов явные:

- Новые задачи создаёт управление. Web сохраняет исходный план при создании,
  Telegram сохраняет стабильный ID/`sourceDraftId`; прежний серверный валидатор
  по-прежнему единолично подтверждает исходный план в сохранённом снимке.
- Web учитывает назначенного проверяющего при завершении задачи; Telegram разрешает
  завершение только управлению. История callback хранит прежний ключ дедупликации.
  Telegram проверяет назначение по ID, web сохраняет совместимость по имени.
- Загрузки web доступны управлению/прорабу. Прежняя возможность связанного участника
  Telegram добавлять приватные записи и документы сохранена, включая роль клиента.
  Это не делает их клиентскими отчётами и не меняет серверные проекции.
- Фото web по-прежнему ограничены десятью JPG/PNG/WebP до 12 МБ, датой съёмки и
  проверенной ссылкой источника. Telegram сохраняет текст, фото и голосовые записи;
  общий транспортный лимит файла остаётся 20 МБ.

Источники, права, исходные сроки, аудируемая история и независимые факты задач,
приёмки, этапов и оплаты сохранены. Нет новых API, таблиц или миграций. Загрузка и
регистрация остаются разными операциями; очистка непривязанного файла не добавлялась.

## Границы интерфейса

`App.tsx` сократился с 402 до 269 строк. Он компонует оболочку и страницы:

- `presentation/useSession.ts` получает сессию и проверяет её по таймеру/видимости;
  401/403 очищает кеш и переводит на вход, временная ошибка связи не отзывает доступ.
- `presentation/useWorkspaceProject.ts` связывает проект с адаптерами синхронизации,
  маршрутом и разрешёнными страницами; saving/conflict по-прежнему останавливают
  автоматическое переключение. Очередь записи и разрешение конфликтов не дублируются.
- `presentation/CreateProjectDialog.tsx` владеет формой создания проекта. Нумерация,
  шаблон проекта и существующий workflow сохранены.

`SettingsPage.tsx` сократился с 700 до 66 строк и компонует секции доступов,
главного экрана, уведомлений и интеграций. Доступы и интеграции имеют отдельные
контроллеры `useAccessSettings`/`useIntegrationSettings`, общие DTO и подписи.
Страница привязана ключом к проекту. При её закрытии старые запросы отменяются;
поздний снимок другого проекта не передаётся в синхронизацию. Последующие запросы
из закрытого контроллера также отвергаются. Серверные права остаются обязательными.

## Проверки

- Node 22.13.0: 508 тестов прошли, один PostgreSQL auth lifecycle пропущен без
  отдельной тестовой БД. Новые сценарии сравнивают web и Telegram, проверяют роли,
  исходные сроки, дубль callback/черновика, ссылки и чужой файл.
- TypeScript, Vite, упаковка Sites и импорт упакованного Worker прошли.
  Сборка Sites проверяется под `/tmp`: прежний `dist` принадлежит другому пользователю.
- Docker-сборка и импорт Worker без сети прошли. Alpine пропускает PostgreSQL и
  две bash-проверки; bash-проверки прошли в полном локальном наборе.
- Chromium с синтетическим API: вкладки настроек, виджеты/уведомления, редактирование
  профиля и сохранение ввода после конфликта, приглашение с выбором проектов,
  поздний ответ после смены объекта, нумерация нового проекта, мобильные поля,
  фокус и кнопка закрытия, сессия 503/401 и ограничения маршрута клиента.
- Отдельные браузерные регрессии: создание/комментарий/проверка/завершение задачи,
  доказательства качества, загрузка документа и приватного фотоотчёта, локальный
  реестр без активации, План 0, структура ППР, история и прогноз.

Браузерные запросы перехвачены; реальные сообщения, доступы и рабочие данные
при проверках не изменялись. Артефакты и журналы проверок: `/tmp/stroios-shared-*`.
