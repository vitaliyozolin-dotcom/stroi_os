# Завершение текущего этапа модульного разделения

## Выполнено

- Финансы: создание обязательств, утверждение, приёмка, оплаты/поступления,
  планирование, распределение и исторический импорт.
- Контрагенты: карточки и записи документов.
- Снабжение: потребности, предложения, выбор поставщика и последовательные статусы.
- Маркетинг: создание, квалификация, этапы, отменяемый импорт без потери свежих данных.
- Решения клиента: подтверждение с проверкой открытого снимка и аудитом сессии.
- Документы проекта: порт загрузки, подготовка метаданных и регистрация через StateChange.
  До загрузки проверяются роль и связи; после ответа повторно проверяются проект,
  отмена и актуальные связи. Сохраняется последний снимок, без перезаписи параллельных
  задач/документов. Загруженный файл проверяется на принадлежность проекту.
- Фотоотчёт: отдельный сценарий с портом загрузки, проверкой фото/ссылки/этапа,
  повторной проверкой проекта, отмены и дублей после каждого файла, приватным отчётом
  и аудитом. Частичный набор файлов не создаёт запись отчёта.
- Настройки: явные команды виджетов, каналов, событий и локального реестра участников.
  Локальный сценарий реестра требует полномочий владельца, проверяет email, роль,
  уникальность и открытый снимок. Действующие серверные API доступа, выдача ссылок
  и привязка Telegram сохраняют прежние маршруты и проверки. Их действия не запускались.
- График: редактирование плана, План 0, структура ППР, сверка состояния, уточнение
  неизвестных дат, историю состояния объекта, общий прогноз и управление этапом передают StateChange с аудитом.
  Существующие чистые валидаторы графика переиспользуются на временной копии;
  сервер повторяет проверку и единолично добавляет доверенную историю/подтверждения.
  Часы и генератор ID управления этапами передаются извне; старый вызов оставлен совместимым.
- Общие функции `page-commands.ts` и `createPageStateSink`, принимавшие готовый
  снимок всей страницы, удалены. Задачи/качество используют существующие предметные
  переходы и StateChange. Навигация остаётся отдельным слоем представления.

## Сохранённые контракты и ограничения

AppState, схема БД, серверная авторизация, ролевые проекции, expectedRevision,
конфликты и аудит сохранены. Производство, DNS, Telegram и реальные данные не менялись.
Настройки каналов в тестах менялись только на синтетических снимках.

Загрузка файла и регистрация метаданных остаются двумя операциями. При отмене
после завершения загрузки непривязанный файл автоматически не удаляется.
После смены проекта или удаления связанной записи регистрация отвергается,
ввод остаётся в форме, пока страница открыта. Файловый сервер остаётся доверенной
границей проверки содержимого, размеров, доступа и хранения.

Это завершает согласованный этап выноса операций из страниц, а не полную DDD-миграцию.
Последующий этап контрактов контекстов и узких репозиториев также выполнен:
актуальный результат описан в [карте контекстов](context-map.md). Чистые общие
политики финансов и строительства находятся в domain; совместимые входы sites
переиспользуют их. Общий AppState остаётся форматом хранения. Делить таблицы
или менять схемы для этих этапов не требовалось.

## Проверки

`remaining-module-use-cases.test.ts` проверяет настройки, реестр, гонки/отмену
загрузки, чужие файлы, План 0, структуру, права подтверждающего и управление этапом.
Действующие тесты ролей, приёмки, финансов, baseline и синхронизации остаются воротами.
Архитектурные тесты запрещают возвращать общий способ записи страниц.

Итоговая проверка 20.10.2026: 438 тестов прошли, один PostgreSQL auth lifecycle
пропущен без отдельной интеграционной БД. TypeScript, полная сборка Sites и Docker
прошли. Браузер на синтетическом активном проекте проверил загрузку документа,
приватный фотоотчёт, виджеты/правила уведомлений, локальный профиль без активации,
План 0, структуру ППР, серверное подтверждение остатка, управление этапом,
историю состояния и общий прогноз. Серверные модули обеих сборок загружаются.
